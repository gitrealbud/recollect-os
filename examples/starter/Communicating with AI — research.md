# Communicating with AI — research

**Purpose:** Evidence and source trails behind the hub practices.  
**Parent:** [[Communicating with AI]]

## Verdict

Effective use of AI assistants depends less on clever phrasing and more on: underspecified tasks being the main failure mode; intentional (not maximal) context; explicit success criteria; and separating standing preferences into durable notes so chat is not the store of record.

## Findings

| Finding | Source class |
|---------|--------------|
| Prompts work best when they separate task, inputs, constraints, and success | Industry practice guides (2025–2026) |
| Irrelevant context competes with signal; more is not always better | Prompt / context engineering writeups |
| Useful structure: context, role or goal, audience, constraints, examples of good output | CO-STAR-style and PR/comms prompting guides |
| Specificity (task, audience, format, constraints) reduces generic output | Multiple practitioner guides |
| Shift from “prompt wording” toward “what the model is allowed to know” (context pipelines) | Practitioner discussion 2026 |
| Standing preferences and decisions should not live only in chat | Aligns with Recollect files-as-SoT |

## What was not claimed

- No single universal prompt template is required.
- No vendor-specific product is endorsed.
- Domain work (code, law, medicine) still needs domain constraints beyond this hub.
